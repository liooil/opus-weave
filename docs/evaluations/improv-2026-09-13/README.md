# DeepSeek 即兴提示词实测

本次使用官方 `deepseek-flash` 接口，完成 144 次真实请求，无请求失败。最终提示词在原场景和移调验证中共 **30/30 次通过协议与衔接检查**；同轮旧提示词为 **0/30**。这是有限场景下的结果，不代表通用音乐质量达到 100%。

| 轮次 | 新提示词通过 | 同轮旧提示词通过 | 调整与发现 |
| --- | --- | --- | --- |
| 初版 | 10/12 | 0/12 | 旧提示词持续漏掉 `N`；初版仍在无空间窗口生成音符 |
| 第二版 | 30/30 | 0/30 | 强调 `N`、无空间只返回 `END`、增加音名线索；仍有不合语境的变化音 |
| 最终版 | 18/18 | 0/18 | 增加声部音域内的 MIDI 候选音，保留较早出现的三音 |
| 最终版移调验证 | 12/12 | 0/12 | 输入与保留声部整体上移五个半音，提示词不再修改 |

最终版的 30 次中有 5 次是预期的无空间休止；其余 25 次都有有效音符，没有通过空答获取通过率。生产客户端会直接跳过完全占满的窗口；评测特意仍发出请求，以验证模型对边界的理解。

## 音乐内容检查

这里检查的是输出音高、时值和上下文关系，没有进行盲听或主观听感评分。

- 繁忙 D 小调输入：前两版出现过 MIDI 66（F#），但输入明确包含 F。最终版三个样本均未再出现 F#；样本使用 D、F、A、C 等输入音级。移调后的两个样本也未出现对应的升高三音。
- C# 大三和弦输入：之前会在片段开头使用 MIDI 72（C）；最终版三个样本开头、结尾均落在观察到的和弦音上，其中一个样本保留了短暂经过音。
- 和声从 C 转向 F：最终版三个样本均围绕 F、A、C 展开。一个样本后半窗口留白，这通过协议检查，但是否符合演奏者期望仍需试听。
- 跨窗口旧音：最终版与移调样本都避开了旧音尾部；移调样本仍出现过八度跳进，说明“格式合法”不等于声部进行最优。

MIDI 候选音只是观察到的音高提示，允许经过音，不锁定调式。当前“同时按住至少三个音优先视为和声依据”的启发式也可能遇到经过音或复杂和弦；尚未测试持续多分钟合奏、踏板累积和复杂转调。

## 方法与复现

六类输入为大调低音、繁忙小调伴奏、含升号和弦、跨窗口旧音、无空间窗口、近期和声变化。每轮新旧提示词使用相同输出预算（4 拍 192 tokens、8 拍 320 tokens）、关闭思考、不覆盖服务端默认采样参数、无重试。顺序在重复之间交替，不是并发压测。

检查项包括完整 `END`、`N` 行格式、音高和时值边界、音符重叠、保留声部冲突和密度上限。音乐复核标记与硬性有效性分开计算。没有修复旧输出再计为通过。

最终原场景首个完整音符行的延迟中位数为 719ms、P90 为 916ms；移调验证分别为 612ms、871ms。休止响应不计入首音符统计。这是当前连接的一次测量，不是首 token、实际发声延迟或服务承诺。无法据此声称提示词提速。

设置 `DEEPSEEK_API_KEY` 环境变量后运行 `bun scripts/eval-improv.ts`；移调验证再设置 `IMPROV_EVAL_TRANSPOSE=5`。测试脚本不会保存密钥。默认 24 次请求；本轮重复数详见各 JSON。

原始返回、延迟、检查结果及可用的提示词快照保存在 [v1.json](v1.json)、[v2.json](v2.json)、[final.json](final.json)、[transposed.json](transposed.json)。初版提示词单独保存在 [prompt-v1.txt](prompt-v1.txt)，旧版固定提示词在 `scripts/fixtures/improv-prompt-baseline.ts`。

本目录的 `final-*.owt`、`transposed-*.owt` 是各场景第一次最终版输出，可在应用中打开试听。乐谱是量化转录；held 列表中没有完整时值的输入不会自动补成持续和弦，因此试听并非完整现场重建。

本地验证：相关 23 项回归测试通过；全量 382 项通过、1 项已有 FluidSynth 环境相关失败；Web 构建通过；类型检查仍有两处已有 `wkwebview` 类型错误，无新增错误。
