# Live improvisation

Open **Improv** (`Ctrl+I`), choose a fixed tempo (40–200 BPM, 4/4), an AI role and volume, then **Start duet** (`Ctrl+Shift+I`). Use musical typing, the virtual piano or MIDI. Human input sounds locally and remains active throughout AI generation and playback. The piano roll shows human notes, performed AI notes and translucent future plans. AI volume changes immediately; role changes apply to the next request.

End the duet, then **Keep in score** (`Ctrl+Shift+S`) to copy the take into the editor. Opening or ending a duet does not replace the existing score. Saving uses sixteenth-note quantization, splits overlapping human notes into OWT voices, and fills measure boundaries; only performed AI notes enter the score. The normal OWT/MIDI/WAV exports remain available. A new session replaces the previous in-memory take.

## Runtime

- `RealtimeImprovSession` uses seconds from the audio context for input, future plans, and note scheduling. Sustained human notes remain in the context until pedal release.
- A single request can run at a time. After human input begins, requests adapt their target cadence between 0.35 and 2.5 seconds using recent completion latency and error backoff. Unchanged input with sufficient planned coverage skips requests; new input or a role change requests an update at the next available slot. Each input snapshot includes at most 64 recent human notes (eight seconds), held pitches and 32 preceding AI notes. Holding a key never blocks generation. Eight seconds without input or held notes stops new requests.
- Each request initially targets eight beats on a future beat boundary. After three event-latency samples, fast connections use four beats and eighth-note alignment; slower connections retain eight beats. Initial lead is 0.8 seconds, adapted within 0.3–3 seconds using the 90th percentile of the last eight first-event latencies plus a 250ms margin. Lead increases immediately for latency spikes and decreases gradually. The output budget is 192 tokens for four beats or 320 for eight beats, with thinking disabled for this workflow only. The selected provider, credentials and usage accounting are reused. Legacy full-OWT prompt templates are not the live event protocol.
- Events stream as `N offset duration pitch velocity`, using integer sixteenth-note offsets and durations. Complete lines are validated immediately. The generator permits up to 6 or 12 notes, with lower role-specific density targets, explicit rests and no minimum quota; it produces notes in one monophonic AI voice; input/output event counts, pitch, velocity, duration, ordering and total response size are bounded.
- The browser pumps every 25ms and commits only the next 150ms to SpessaSynth's audio worklet with explicit audio-context timestamps. Events outside that horizon can be replaced. Late note-ons are dropped, never replayed in a burst. Committed note-offs survive replanning. Empty or unusable replacements preserve the previous plan.
- An extra synthesizer channel isolates AI from all 16 hardware MIDI channels. Ending a session mutes it immediately, including pending note-ons. Restart waits for the old scheduling horizon to drain before unmuting. Human audio stays independent.
- Streams have an eight-second timeout. Failures back off exponentially, capped at 30 seconds, while valid scheduled music can finish. Session versions reject stale completions. Leaving the tab ends the duet to avoid background timer throttling; score playback, a new document and other AI work also end live playback.

The official DeepSeek preset uses `deepseek-flash` (V4.1 Flash). Stored official-host V4 Flash aliases migrate to this ID; custom proxy model names remain unchanged. The model catalog includes image input, but live improvisation still uses symbolic MIDI context. Cost estimates use peak rates; off-peak billing may be lower. The stable system prompt is shared across roles and window sizes to allow provider prompt caching.

## Validation and limits

`src/tests/realtime-improv.test.ts` covers partial/cumulative streams, invalid events, concurrent human input, replacement boundaries, late arrivals, stop/restart, sustain, backoff, provider request parameters and playable OWT archives. Engine tests cover timestamped scheduling and isolated cancellation. Browser checks use a mocked AI endpoint with the actual bundled synthesizer and SoundFonts.

The assumed 100 tokens/second is not a measured service guarantee. First-token latency and network jitter determine how far the AI must plan ahead. Connection details expose first usable event latency, future coverage, dropped notes, adaptive lead and target refresh interval. This version uses fixed tempo and a single AI voice; it does not infer free tempo or generate audio samples with the model. Archive timing is quantized and bar-spanning notes are split, so the score is an editable transcription rather than an exact audio recording.

## Prompt evaluation

The live default is in `src/domain/ai/improv-prompt.ts`. It supplies target bar position, observation time, a conservative earliest onset after retained AI tails, role-specific register/density guidance, and explicit permission to rest. Recent harmony takes priority over old history; held pitches are observations, not future guarantees. Named pitch classes and role-register MIDI candidates reduce pitch-number ambiguity. Candidates use a held chord when at least three pitches are held, otherwise up to four beats of observed material to retain thirds missed by the two-beat snapshot; they are suggestions, not a detected key or a hard scale. A fully occupied window bypasses generation in production; evaluation deliberately sends that case to measure prompt compliance. The parser rejects overlaps and events after `END`; the client reports a missing `END` as truncation. Already streamed valid events remain usable.

Run `bun scripts/eval-improv.ts` with `DEEPSEEK_API_KEY` already set in the environment. Optional variables: `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`, `IMPROV_EVAL_REPEATS` (default 2, capped at 5), `IMPROV_EVAL_DIR` (default a timestamped `/tmp` directory), and `IMPROV_EVAL_TRANSPOSE` (integer semitones, bounded to ±12). The default is 24 sequential requests: six scenarios, two prompts and two repetitions. Each request has a 20-second timeout and no retries. The frozen baseline is the preceding production prompt. Both variants use identical generation settings and output budgets; their order alternates across repetitions.

Scenarios cover major-key bass, busy minor-key input, chromatic held harmony, carried AI notes, a fully occupied target window and a recent harmony change. `results.json` preserves raw outputs, protocol validity, carried-note collisions, review flags and response timing. Matching `.owt` files allow listening in the app. First-line timing measures reception of a syntactically complete note line, not audible latency. Large leaps, register excursions and sustained semitone clashes are review flags, not proof of bad music. Silence is valid but needs contextual listening. Compare complete-response validity and request failures separately, then listen for harmonic fit, space, continuity and rhythmic response; a small sample cannot establish a reliable success-rate improvement.

Local regression tests verify the prompt context and rejection boundaries using synthetic responses. Actual model A/B evaluation requires a configured connection; synthetic tests alone do not establish real-model improvement. See the dated evaluation report for measured results.
